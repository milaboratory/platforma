Column value references: `ColumnValueId` names one value of a column a block picked, and template relocation repoints the producer block inside it.
A model builds value pickers over a column with `readColumnValues(recipe)` — every non-empty cell of a column stored inline as JSON (`PColumnData/Json` / `PColumnData/JsonPartitioned`), with its key, value and `ColumnValueId`; `undefined` while the data is not ready or when the column's data cannot be read in the model — and `deriveColumnValueOptions(entries)`, the distinct values as `{ value: ColumnValueId, label }` options in natural order of labels.
In workflows, `workflow.column-value` reads such ids back into plain values: `valueOf` for one id, `valuesOf` for an array of them.
A block reads which blocks below it reference its outputs with `ctx.getOutputDependencies()`: one entry per dependent block and referenced column (plain output, or a filtered, discovered or overridden column over it), with the values of that column the dependent block picked, or `null` when it uses the column as a whole; recomputed whenever any block's args or the project structure change; `undefined` on a runtime that does not provide it.
A block reads its own id with `ctx.blockId`; `undefined` on a runtime that does not provide it.
The `blockDependencies` plugin (plugin id `dependencies`) adds two outputs to a block that registers it with `.plugin(blockDependencies)`: `dependencies` — outputs of other blocks the block's args reference — and `dependents` — blocks whose args reference the block's outputs. Each reference carries the picked values and a status checked against what the producer's last run exports: whether the column is exported and whether it holds the picked values. A reference to an output its producer does not export is `broken`: as `unavailable` among `dependencies`, as `notExported` among `dependents` — the dependent block cannot run against it. A reference that cannot be checked is `unchecked` with a reason: `unreadable` — the column's values cannot be read; `unsupported` — the runtime cannot list the last runs of the blocks above. Each reference carries the column's label: the exported column's, or, when the producer's last run does not export it, that of the column the producer prepares before it is run; the status is still judged by the last run alone.
`PlBlockDependencies` (`<PlBlockDependencies :handle="app.plugins.dependencies.handle" />` on a `PlBlockPage` with a title) shows these links: a header button opens a panel listing the blocks that use this block's outputs and the outputs this block uses, with picked values and status, an unchecked link's tag naming why it was not checked, and an output another block uses that this block does not export tagged as an error. In place of the component, one alert per side lists the links that need attention: an error when an output this block uses is unavailable or lacks picked values; for the blocks using this block's outputs, an error when one of them uses an output this block does not export, a warning when they only pick values this block's output lacks. Columns are named by their label; output names are shown only as hints. Outputs of one block that are not exported and have no known label share one alert line ("uses 2 outputs this block does not export"), and a panel row names such an output "Unavailable output". Block names in the panel and the alerts open that block, when the app can open blocks.
`PlBlockName` (`<PlBlockName :block-id="id" :name="label" :on-open="onOpen" />`) shows the name of another block of the project: a link opening that block when the app can open blocks, calling `onOpen` first, and plain text otherwise.
Block UIs can ask the app to open another block of the same project: `PlatformaV3` has an optional `openBlock(blockId)`, absent in app versions that cannot do it; in Vue, `useOpenBlock()` returns a function opening a block by id, or `undefined` when the app cannot.
