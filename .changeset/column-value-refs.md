Column value references: `ColumnValueId` names one value of a column a block picked, and template relocation repoints the producer block inside it.
A model builds value pickers over a column with `readColumnValues(recipe)` — every non-empty cell of a column stored inline as JSON (`PColumnData/Json`), with its key, value and `ColumnValueId`; `undefined` while the data is not ready or when the column's data cannot be read in the model — and `deriveColumnValueOptions(entries)`, the distinct values as `{ value: ColumnValueId, label }` options in natural order of labels.
`columnValueLabel(picked)` names a picked value to the user: the value a column value id picks, or the string as is when it is not such an id.
In workflows, `workflow.column-value` reads such ids back into plain values: `valueOf` for one id, `valuesOf` for an array of them.
The middle layer computes the column links of each block: `dependencies` — outputs of other blocks the block's args reference: its current args, else those of its last run, as `argsSource` says — and `dependents` — blocks whose args reference the block's outputs, with `hasUnrunChanges`, whether the block has changes its last run does not include. They reach the app and the block UI as `columnLinks` of the block state (`BlockStateInternalV3`, `BlockStateV3`); `undefined` while they are not computed, and in app versions that do not compute them. They are computed only for blocks whose model declares the `supportsColumnLinks` feature flag, which `BlockModelV3` sets, so blocks built with an earlier SDK add no work. Each block's links are computed on their own: its dependencies read its args and the last runs of the blocks they reference, its dependents read the args of the blocks below it and its own last run, so a run of one block does not recompute the links of blocks that do not reference it. Each reference carries the picked values and a status checked against what the producer's last run exports: whether the column is exported and whether it holds the picked values. A reference to a block that has no last run is `notRun` on both sides: the block has to be run first. A reference to a block whose last run is still rendering its results is `pending`; one whose last run failed to render them is `broken`. A reference to an output its producer does not export is `broken`: as `unavailable` among `dependencies`, as `notExported` among `dependents` — the dependent block cannot run against it. A reference to a block that is not above the block holding it is `unavailable` too. A column counts as exported once its spec is in the producer's last run; picked values are checked against those its `pl7.app/discreteValues` annotation lists, else against its data. A reference whose column values cannot be read is `unchecked`, with the reason `unreadable`. Each reference carries the column's label: the exported column's, or, when the producer's last run does not export it, that of the column the producer prepares before it is run; the status is still judged by the last run alone. Blocks are labelled by their titles, the names the project shows.
`linkSections(columnLinks)` and `linkAlerts(sections)` turn column links into the alerts an app shows above a block, one per side, for the links that need attention: an error when an output this block uses is unavailable or lacks picked values; a warning, with advice to add the missing data to this block or reconfigure those blocks — or, while the block has changes not run yet, a note that the links are checked against its last run — when blocks using this block's outputs use an output it does not export or pick values it lacks; links to a block that has not been run yet raise both alerts too, the warning asking to run the block. Columns are named by their label; output names are shown only as hints. Outputs of one block that are not exported and have no known label share one alert line ("uses 2 outputs this block does not export"). `describeMissingValue(dependencies, value)` tells which block was to provide a missing column or column value and what went wrong. `computeDependencies`, `computeDependents`, `labelColumnLinks`, `linkSections`, `linkAlerts` and `describeMissingValue` are in `@milaboratories/pl-model-common`.
`PlBlockDependencies` (`<PlBlockDependencies />`) shows those alerts in a block UI that places it, from the column links the app provides, and nothing when it provides none; each other block is named by `PlBlockName`.
`PlBlockName` (`<PlBlockName :block-id="id" :name="label" />`) shows the name of another block of the project: a link opening that block when the app can open blocks, and plain text otherwise.
Block UIs can ask the app to open another block of the same project: `PlatformaV3` has an optional `openBlock(blockId)`, absent in app versions that cannot do it; in Vue, `useOpenBlock()` returns a function opening a block by id, or `undefined` when the app cannot.
`PlDropdown` and `PlDropdownMulti` show a selected column value id by the value it picks: as is while the options load, and as "<value> — not available" when the options lack it, unless `missingValueLabel` is given.
`PlValueLabel` (`<PlValueLabel :value="item" :options="options" />`) shows a selected value as text the way a dropdown does: by its option's label, a column value id by the value it picks, and a value the options lack as not available, in error color.
`PlDropdown`, `PlDropdownMulti`, `PlDropdownRef`, `PlDropdownMultiRef` and `PlValueLabel` take `missingValueHint`, a function giving the content of a tooltip that explains a missing value, or `undefined` when there is nothing to tell. The ones `@platforma-sdk/ui-vue` exports pass it themselves when the app provides column links, for a missing column — selected by id or by ref — and a missing column value: the tooltip names the block that was to provide the column, as a link to it, and what went wrong — it does not provide the column, the column lacks the value, the block is still computing it, or the block has not been run yet.
`PlDatasetSelector` explains a selected dataset or filter the options lack the same way, by the column it selects: the dataset first, then its filter.
`PlDropdownRef` and `PlDropdownMultiRef` show a missing value as "Value not available", like the other dropdowns, instead of "Upstream value removed".
Inside a `PlTooltip`, `--txt-link` is the tooltip link color, so links drawn with it — `PlBlockName` among them — read on the dark tooltip background like the tooltip's own links.
