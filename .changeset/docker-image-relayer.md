Opt-in re-layering of docker images by package before the push: set `PL_DOCKER_RELAYER=chunkah`.
The built image is exported, every file is tagged with the package that owns it (pip, conda and
Debian package databases; the image's WORKDIR as its own group; other files by directory), and
[chunkah](https://github.com/coreos/chunkah) writes an OCI image with one layer per package or
group of packages (at most 64). crane pushes it. A package above 2 GiB is split into several
layers. Works for every docker image package-builder pushes, not only the autogenerated python
ones. The image config is kept; only the pushed image is re-layered, the local one is unchanged.

Why: an unchanged package then gives a byte-identical layer, so a one-package bump uploads, and
a node pulls, about one package instead of the whole dependency layer. On a 7.9 GB GPU python
image a one-package bump pushed in 9 s and pulled in 23 s (vs 766 s and 1040 s with one
dependency layer).

The tools run as pinned container images on the same docker daemon (no installs on the runner);
registry credentials are read from the docker config / credential helper on the host and given
to crane on stdin. Layer sizes of the re-layered image are checked by compressed size against
`PL_DOCKER_MAX_LAYER_BYTES` (warning by default).

Autogenerated python images now compile `.pyc` hash-based instead of from the install time, so
an unchanged package gives the same files on every build.
