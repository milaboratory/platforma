Autogenerated python images no longer put all dependencies into one layer. `pip install` still
runs once (one resolution), in a build stage; the installed `/usr/local` tree is then split into
8 directories of about 2 GiB each (more when the tree exceeds 16 GiB), and the final image
copies each as its own layer. A directory too big for any layer is split into its children, so
a layer exceeds the target by less than one file. Trees under 2 GiB still land in one layer.
Packages stay in `/usr/local`, on the same base image and interpreter, so entrypoints and
blocks need no change.

Why: registries finalize an uploaded layer in one request, and the pushing client waits a fixed
time for it (30 s in containerd >= 2.3, which Docker >= 29.7 uses). Multi-GB dependency layers
failed to push with `timeout awaiting response headers` after a full build.

After every docker build, layers above 4 GiB (uncompressed) are reported with the instruction
that created them. This is a warning by default; set `PL_DOCKER_MAX_LAYER_BYTES` to make an
oversized layer fail the build before the push.
