Block action context in templates. `render()` sets the action context of the rendered template from the action context of the current renderer: a new `ActionContext` with a copy of the parent context baggage and its own `name` (the imported template name, or the new `name` option), linked from the parent context; the sinkhole when the current renderer is in the sinkhole; nothing when it has no action context. The render's `actionContext` field is one-time-writable, so the template cannot change it. `render(tpl, inputs, { actionContext: false })` puts a template and everything below it into the sinkhole. `self.actionContext()` and `smart.resource.status()` return a handle with `record(namespace, state, ...detail)` and `setReading(namespace, key, value)`, which are no-ops unless the backend supports block action context reports (`feats.actionContextApi`); `self.actionContext().baggage()` returns the baggage of the current context (e.g. `run-id`, `block-id`), and `self.actionContext().create(data)` creates the context of a template rendered without an action context.
