Fail a CI build that describes software with no docker image. An image is autogenerated only for
`python` and `conda` artifacts, so a `java`, `R` or plain `binary` entrypoint without an explicit
`docker:` block used to publish a descriptor carrying only `binary` — which no kubernetes
installation can run: the runner fails the command at execution time with "docker image is not
specified". The check reads the package's declaration rather than what a given run built, so
partial builds (`--variant binary`) stay valid, and it is skipped outside CI so mid-edit packages
do not block local iteration. A deliberately binary-only package declares itself with
`"block-software": { "requireDocker": false }`.
